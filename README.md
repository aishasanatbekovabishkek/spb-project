# Job Application Tracker

Курсовой проект по дисциплине «Конструирование программного обеспечения».
Санкт-Петербургский политехнический университет Петра Великого, 2026 год.

## 1. Описание проекта

Job Application Tracker — веб-приложение для поиска вакансий и управления откликами на работу.
При активном поиске работы информация о вакансиях, собеседованиях, откликах и их статусах часто оказывается разбросанной по разным сервисам. 
Приложение позволяет объединить эту информацию в одном месте и отслеживать процесс трудоустройства.

**В качестве основного работающего внешнего источника данных используется API Trudvsem** (так как HeadHunter начал возвращать ошибку 403).

## 4. Пользовательские сценарии

- **US1:** Поиск вакансий по ключевым словам.
- **US2:** Сохранение интересующих вакансий.
- **US3:** Создание откликов и изменение статусов.
- **US4:** Просмотр истории изменения статусов.
- **US5:** Просмотр статистики откликов.

Дополнительно предусмотрены авторизация, фильтрация вакансий и напоминания.

## 5. Архитектура

Выбрана клиент-серверная архитектура.
Backend проектируется как модульный монолит, реализованный на FastAPI.
Frontend взаимодействует с Backend через REST API.
PostgreSQL используется для постоянного хранения, Redis — для кэширования внешних данных.

**Архитектурные диаграммы:**
- C4 System Context
- C4 Container
- ER-диаграмма
- REST API Contracts

**Нагрузочное проектирование:**
Документ включает:
- оценку Read/Write нагрузки;
- расчёт RPS и сетевого трафика;
- оценку хранения данных за 6 лет;
- масштабирование до 100 000 DAU;
- стратегию кэширования и отказоустойчивости.

## 6. MVP (Текущий статус)

Минимальная версия (MVP) полностью реализована и работает:
1. Регистрация и авторизация.

3. Сохранение вакансий.
4. Создание откликов.
5. Изменение статусов.
6. Просмотр истории изменений.

## 8. Тестирование

В рамках проекта настроен полный цикл тестирования:
- **Unit и интеграционное тестирование (Pytest):** В проекте настроены тесты, покрывающие бизнес-логику бэкенда и работу с базой данных PostgreSQL (все 22 теста проходят успешно).
- **E2E-тестирование (Playwright):** Разработан полноценный сквозной сценарий на Python, который имитирует действия реального пользователя (регистрация, поиск, сохранение, отклик, смена статуса, история). Тест упакован в Docker-контейнер.

**Как запустить тесты:** Подробная пошаговая инструкция находится в файле [docs/release-guide.md](docs/release-guide.md).

## 9. Развёртывание

Проект полностью контейнеризирован с помощью **Docker Compose**. Это позволяет развернуть всю систему (базу данных, кэш, бэкенд и фронтенд) на любой целевой машине, где установлен только Docker, одной командой.

**Запуск проекта одной командой:**
Для сборки и запуска всех сервисов необходимо выполнить следующую команду в корневой папке проекта:

    docker compose -f docker-compose.yml -f docker-compose.frontend.yml up -d --build

**Что автоматически происходит при запуске:**
1. Поднимается база данных PostgreSQL и Redis (проверяется их статус Healthy).
2. Автоматически применяются миграции базы данных (Alembic).
3. Собирается и запускается бэкенд на FastAPI.
4. Собирается фронтенд на React и раздается через веб-сервер Nginx.

После успешного запуска приложение будет доступно в браузере по адресу: `http://localhost:8080`.

**Полная документация:** Пошаговая инструкция по настройке переменных окружения, запуску проекта, а также запуску всех видов тестов находится в файле [docs/release-guide.md](docs/release-guide.md).
